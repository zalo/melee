Game Information
Title: Super Smash Bros. Melee (native)
URL: https://github.com/zalo/melee/tree/portmaster (game code from https://github.com/doldecomp/melee, rendering by https://github.com/encounter/aurora)

Instructions:
Copy your own US 1.02 disc image (GALE01; .iso, .gcm, .ciso or .rvz) into ports/melee/assets/.
Any file name works; the launcher picks the first image it finds there. No other game data is
needed or shipped; the port reads everything from your image.
Launch "Super Smash Bros. Melee (native)" and answer Yes at the memory-card prompt (saves are
Dolphin-compatible .gci files under ports/melee/runtime/config).
The first matches stutter while shaders compile; please report FPS from the second launch on,
and attach ports/melee/log.txt to every report.
Port options: main menu > Options > Port Settings (the fourth row). "Unlock All Characters and
Stages" saves at once; the game then shows its trophy pop-ups once on the next menu visit.
"Debug Overlays" turns on Melee's own hitbox/hurtbox bubbles in matches (R2 + left stick up),
"Debug Menu" lets Y on the title screen open the developer menu. Both default to off.

Second testing zip (2026-09-19), what changed after the first reports:
- The first zip had SDL's KMSDRM video driver missing (a configure-time slip; only the Wayland
  driver was compiled in), so every KMSDRM CFW failed with "No available video device", which
  the launcher misreported as an OpenGL driver problem (RG552 on AmberELEC). Fixed; the build and
  CI now refuse to package a binary without KMSDRM + Wayland video and ALSA + PulseAudio +
  PipeWire audio. Please retest AmberELEC / ArkOS / Knulli with this zip.
- No sound on ROCKNIX: ROCKNIX exports SDL_AUDIODRIVER=pulseaudio to ports and the first build had
  no PulseAudio backend. Both PulseAudio and PipeWire backends are in now, and if the backend the
  CFW names is unavailable the next one is tried instead of playing nothing.
- When the display cannot be opened, log.txt now lists the video drivers in the build, the
  /dev/dri nodes and SDL's reason for rejecting each driver.
- SDL, as requested: SDL is no longer built in. The game links SDL 3 (Aurora renders through it)
  as a shared library, and libs.aarch64 carries the SDL3-over-SDL2 shim that Dusklight ships
  (bmdhacks/SDL, branch sdl2-backend). Display, audio and pads now go through this CFW's own
  libSDL2-2.0.so.0 with all of its device patches (KMSDRM, fbdev, Wayland, rotation, audio
  server), so fbdev CFWs such as muOS and H700 Knulli should work too. Reports from those are
  the most useful now. The CFW's SDL_VIDEODRIVER / SDL_AUDIODRIVER are handed to that inner SDL 2
  unchanged.
- Reported RG552/ROCKNIX behaviour: the 4:3 pillarbox is intentional (the game is 4:3), the slow
  first half-minute of the first match is Mesa compiling shaders and should be gone from the
  second launch on; please say whether it is.
