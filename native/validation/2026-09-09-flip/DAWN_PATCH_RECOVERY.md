# Dawn patch publication correction, 2026-09-10

The initial fork commit `959822528` published the wrong content in
`native/platform/flip/dawn-egl-native-window.patch`: a diff of the enclosing
Melee repository, rather than the locally modified Dawn source. The direct-GL
hooks were present in the local build but absent from the published source
patch. The initial handoff's Dawn patch-validation claim was incorrect.

## Cause

Dawn was extracted from an archive into `build/flip-tools/dawn-<revision>` and
had no Git repository of its own. Running `git -C <dawn> diff` discovered the
parent Melee repository. Worse, `git apply --check` and its reverse check from
that nested directory could skip paths outside the directory prefix and report
success. The preparation tool therefore did not establish that Dawn was patched.

The fix sets `GIT_CEILING_DIRECTORIES` to the dependency's parent and clears
inherited Git repository/worktree/index overrides for patch subprocesses. An
actual dependency checkout still works; an archive is patched independently of
the enclosing repository. Missing files and conflicting source now fail the
check instead of silently accepting a skipped patch.

## Recovered source

The corrected patch was generated by comparing the local working Dawn files
directly with the original archive, not by discovering a Git repository.

## Validation

The original checksum-pinned archive was extracted into a fresh temporary
directory nested under the Melee repository, reproducing the problematic layout.
The corrected preparation helper applied the published patch twice. Every one
of the archive's 99,136 regular files then matched the working Dawn source
byte-for-byte. A reverse check isolated from the parent repository passed.
Aurora's already-applied patch also passed the corrected helper's idempotence
check.

Four preparation regression tests cover archive patching within a parent
repository, an actual dependency checkout, rejection of a parent-only patch,
and rejection of conflicting dependency content. Together with the existing
launcher/deployment tests, all 20 tests pass:

```sh
python3 native/tests/test_flip_prepare.py
python3 native/tests/test_flip_launcher.py
python3 native/tests/test_flip_deploy.py
```

This correction recovers the existing locally built renderer code; it does not
introduce another graphics optimization. No fresh full SDK build or gameplay
test was performed for the packaging correction. The device was not changed.

## Existing clones

Pull the latest `miyoo-flip` branch, rerun the preparation step documented in
[FLIP.md](../../FLIP.md), then rebuild the game. The default preparation step
builds and installs the corrected Dawn library and generated headers before
building Aurora/the game. `--prepare-only` applies the source patches but skips
that Dawn build, so it is insufficient by itself if Dawn was already built
without the hooks. The ROM does not need to be transferred again.

If local reconstruction has already changed Dawn, preserve those edits before
preparing a fresh dependency tree. A partial or conflicting patch state is
intentionally rejected; the preparation tool does not overwrite it.
